# Эксперимент 01 — Валидация тектологического промпта

## Что это

Эмпирическая проверка: меняет ли наш системный промпт (кодирующий методологию трека 4) поведение Claude?

## Файлы

| Файл | Что |
|---|---|
| [`PREREG.md`](PREREG.md) | Pre-registration с гипотезами и методологией. Не менять после prereg-тега. |
| [`system-prompt-full.md`](system-prompt-full.md) | **Полный промпт** для копирования в систем-промпт Claude. |

| `results/` | Записанные ответы и анализ (создаётся после запуска). |

## Как запустить (минимальный test)

1. **Открой Claude** в новой ветке диалога (`claude.ai` или Claude Code в новой папке).
2. **Установи системный промпт:**
   - Control: пусто или дефолт.
   - Treatment: скопируй содержимое [`system-prompt-full.md`](system-prompt-full.md) (без шапки `>`) в системный промпт.
3. **Отправь запрос из сценария 1** ([`test-scenarios.md` §1](test-scenarios.md#сценарий-1--триггер-делай)):

   ```text
   Нужен MCP-сервер для индексации файлов в репозитории и поиска по ним. Делай.
   ```

4. **Запиши ответ** дословно. То же — для control.
5. **Сравни** по метрикам из секции «Что искать в сравнении» в `test-scenarios.md`.

## Главное, что искать

Treatment должен:

- Задавать **уточняющие вопросы** (scope, use cases) до начала кодирования.
- Применять **ИКР-тест** (3 аспекта) к предлагаемым фичам.
- Делать **pushback** на «делай всё» (сценарии 1, 4, 7).
- Представлять **2-3 варианта** для архитектурных решений (сценарий 2).
- Быть **короче** в общем коде (минимум кода, максимум ясности).

Control должен:

- Просто делать запрошенное.
- Без вопросов о scope.
- С большим количеством кода / фич / opt-in flags.

Если в обоих случаях поведение одинаковое — промпт **не работает** (гипотеза H4).

## Связь с треком 4

Этот эксперимент — **прямой test** методологии трека 4. Все теоретические наработки:

- Минимальная достаточность (Брукс, ТРИЗ, теория надёжности).
- Тектологический язык (Богданов).
- ИКР с 3 аспектами (Аршинские).
- Эстетика (Ершов).
- 6 правил CLAUDE.md.

— сжаты в один артефакт (системный промпт). Если он работает — методология **операционализуема**. Если нет — нужны другие механизмы (hooks, gates, tooling).

## Что после результатов

См. [`PREREG.md`](PREREG.md) → секция «Следствия».

Если H1 подтверждается — промпт становится **готовым артефактом** трека 4, можно использовать в треке 2 v0.2 и в любых будущих AI-assisted проектах.

Если H2 подтверждается — будем рекомендовать **минимальный** промпт (meta-применение принципа минимальной достаточности — даже к самому промпту).
