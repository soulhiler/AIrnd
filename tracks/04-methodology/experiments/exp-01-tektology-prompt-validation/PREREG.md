# Pre-registration: эксперимент 01 — валидация тектологического промпта

> **Создано:** 2026-05-23. После этого commit с тегом `prereg/exp-01/2026-05-23` — менять PREREG нельзя, только дополнять как «amendment».

## Простыми словами

Мы написали системный промпт для AI-помощника (Claude), который кодирует все наработки трека 4: минимальную достаточность, ИКР-тест, 6 правил, тектологический язык Богданова, эстетику Ершова. Теперь хотим **проверить эмпирически** — действительно ли промпт меняет поведение AI?

Если промпт **работает** — это эмпирическое подтверждение, что методология трека 4 операционализуема и приносит измеримую пользу. Если **не работает** — нужно переосмыслить.

## Гипотезы

### H1 (главная) — промпт меняет поведение AI

**При тех же запросах** Claude с системным промптом (treatment) даёт **систематически отличающиеся** ответы от Claude без промпта (control). Различия должны быть **в направлении** методологии трека 4: больше вопросов, меньше кода, ИКР-тест, pushback на «делай всё».

Метрика: на 7 тестовых сценариях (см. `test-scenarios.md`) — treatment-ответы отличаются от control по ≥4 из 6 критериев (длина, вопросы, pushback, ИКР, тектологический язык, субъективная оценка).

### H2 — полный промпт сильнее минимального

`system-prompt-full.md` даёт **более выраженное** изменение поведения, чем `system-prompt-minimal.md`. Но полный также может быть **избыточным** — минимальный может покрыть 80% эффекта при 20% размера.

Метрика: измеренный эффект полного промпта vs. минимального. Гипотеза подтверждается, если полный даёт прирост ≥30% по сумме метрик.

### H3 — pushback на «делай всё» (сценарий 1 и 4)

**Это самые сильные сигналы** overcoding. Treatment должен отказываться от «делай всё» или существенно модифицировать запрос. Control — нет.

Метрика: на сценариях 1 и 4 — наличие явного pushback в treatment (yes), отсутствие в control (yes/no).

### H4 (нулевая) — промпт не работает

Возможный negative результат: Claude, обученная на массиве данных, **уже** в дефолтном поведении делает многое из методологии трека 4. Промпт даёт только marginal эффект.

Метрика: на ≥4 из 7 сценариев нет существенной разницы между control и treatment.

## Методология

### Условия эксперимента

- **Control:** Claude в новой ветке диалога без системного промпта.
- **Treatment full:** Claude в новой ветке с `system-prompt-full.md` в начале диалога.
- **Treatment minimal:** Claude в новой ветке с `system-prompt-minimal.md` в начале диалога.

### Запросы

7 тестовых сценариев из `test-scenarios.md`. Каждый запрос **идентичен** в трёх условиях (control / full / minimal). Запрос подаётся одним сообщением, без дальнейшего диалога — оценивается только первый ответ AI.

### Измерения

Для каждого ответа фиксируется (см. `test-scenarios.md` для деталей):

1. **Длина ответа** (символов; число строк кода если был код).
2. **Был ли pushback** (явный отказ или модификация запроса).
3. **Был ли вопрос перед действием** (уточняющий вопрос).
4. **Был ли ИКР-тест** (упоминание трёх аспектов или эквивалентного reasoning).
5. **Использовал ли тектологический язык** (Богданов: активности, сопротивления, организованность). Только для full prompt.
6. **Субъективная оценка ответа** (от 1 до 5, где 5 = идеально соответствует методологии трека 4).

### Сбор данных

- Я (архитектор-человек) запускаю запросы в новых ветках Claude.
- Записываю ответы дословно в `results/scenario-NN.md`.
- Заполняю таблицу метрик в `results/metrics-table.md`.

### Subjective bias

Признаём: оценка субъективна, т.к. я (автор методологии) также оценщик. Mitigation: **записываю** ответы дословно — третья сторона может пере-оценить.

## Stop conditions (когда останавливать эксперимент)

- **Полный stop:** все 7 сценариев × 3 условия = 21 ответ записан и оценен.
- **Early stop с positive:** если на первых 3 сценариях все метрики treatment > control по ≥4 критериям — эксперимент **показал эффект**, можно ускорить cleanup и зафиксировать.
- **Early stop с negative:** если на первых 3 сценариях нет различий ни по одной метрике — гипотеза H4 (промпт не работает) **очень вероятна**, можно остановиться и переосмыслить промпт.

## Ожидаемые результаты (priors)

Перед запуском (для честности):

- **H1 (главная) скорее подтвердится.** Промпт явно директивен — Claude следует инструкциям. Эффект **должен** быть заметен. Confidence: 0.75.
- **H2 (полный > минимальный):** скорее подтвердится. Полный содержит больше конкретных правил. Confidence: 0.65. Но возможно, что **разница невелика** — Claude уже умеет следовать общим принципам.
- **H3 (pushback на сценарии 1, 4):** уверенно подтвердится. Confidence: 0.85. Это самый прямой тест.
- **H4 (нулевая):** маловероятна, но возможна для **некоторых** сценариев (например, сценарий 6 о тектологическом языке — Claude может **не знать** Богданова достаточно глубоко).

## Уточнения для воспроизводимости

- **Модель:** Claude (последняя доступная версия в Claude.ai веб-интерфейсе или Claude Code).
- **Температура:** дефолт (не настраивается в публичном интерфейсе).
- **Время:** запуск в течение 1-2 дней после prereg.
- **Контекст:** **новый чат** для каждого условия. Без предыдущей истории.

## Открытые вопросы перед запуском

1. **Q1:** Должен ли быть **рандомизированный порядок** запуска (control/treatment)? Чтобы не «учиться» на ответах. Решено: да, рандомизирую вручную.
2. **Q2:** Сколько **повторений** на условие? Из-за non-determinism Claude (даже с фиксированной seed) ответы могут варьировать. Решено: 1 ответ на условие (минимум для prereg), но если результат **неоднозначный** — повторю.
3. **Q3:** **Контроль на artifact знания моего трека.** Я являюсь автором методологии — могу влиять на интерпретацию. Mitigation: дословная запись ответов, открытая публикация (любой может re-оценить).

## Следствия

### Если H1 подтверждается (промпт работает)

- Методология трека 4 **операционализуема**.
- Промпт — **готовый артефакт** для использования в любых AI-assisted проектах.
- Cross-track: можно использовать для трека 1, трека 2 v0.2, и т.д.
- Промпт становится частью deliverables трека 4.

### Если H1 не подтверждается (промпт не работает)

- Методология **не операционализуется** через системный промпт.
- Нужны другие механизмы (внешние gates, hooks, tooling, не промпт).
- Переосмыслить: может быть, методология **слишком абстрактна** для прямого encoding в промпт.

### Если H2 подтверждается (полный > минимальный значительно)

- Полная версия — **рекомендуемая**.
- Минимальная — для случаев, где длина критична (короткий контекст).

### Если H2 не подтверждается (минимальный достаточен)

- Минимальный промпт — **рекомендуемый** (по правилу минимальной достаточности — meta-принцип!).
- Полный — overkill.
- Это **сам по себе** интересный результат: методология сжимается до 3 правил.

### Если H3 подтверждается (pushback работает)

- Самые сильные триггеры overcoding **детектируются** промптом.
- Это **минимальная полезная функция** промпта.

### Если H3 не подтверждается

- Промпт **не справляется** с главными триггерами — серьёзная проблема.
- Нужна **более сильная** формулировка правила #1 и #2.
