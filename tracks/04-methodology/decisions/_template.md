## ИКР — идеальный конечный результат

**Простыми словами:** ИКР — это вопрос «а что было бы, если бы этой фичи **не существовало**, а её задача всё равно как-то решалась?». Если ответ «всё было бы примерно так же» — фичу не надо делать.

Этот раздел — обязательный. Основа — ТРИЗ (Альтшуллер) + формализм Аршинских (2019, [lit-review #4](../lit-review/arshinskiy-2019-software-systematization.md)).

### Три аспекта необходимости (по Аршинским)

По формальному определению Аршинских: «объект A необходим для B, если без A объект B не может в полной мере существовать, функционировать или достигать целей». Это разделяется на **три аспекта**:

1. **Экзистенциальный (e):** Без этой фичи — **существует ли** система вообще?
   - Пример «да»: без `asp_readFile` → ASP-сервер не существует как протокол.
   - Пример «нет»: без `asp_findByTag` → ASP-сервер существует, просто без поиска по тегам.

2. **Функциональный (f):** Без этой фичи — **работает ли** система (хотя бы частично)?
   - Пример «да»: без `asp_listFiles` → нельзя navigate, базовый use case сломан.
   - Пример «нет»: без LLM rerank → retrieve работает, просто результаты хуже отсортированы.

3. **Целевой (g):** Без этой фичи — **достигается ли цель** пользователя?
   - Пример «да»: без `asp_impact` → пользователь не видит blast radius, основная цель ASP-сервера (помощь в навигации) ущербна.
   - Пример «нет»: без hierarchical tags → цель помощь достигается, просто менее удобно.

**Правило принятия:**

- Если хотя бы один аспект даёт «да, без фичи разрушится» — фичу **можно** рассматривать (но дальше пишем какой аспект и почему).
- Если **все три аспекта** дают «нет, без фичи всё ОК» — фичу **не делаем**, отказываемся.
- Иерархия аспектов (по Аршинским): существование первично, функция вторична, цель третична. Если фича нужна только для цели — это **слабее**, чем нужна для функции, и она слабее, чем нужна для существования.

### Дополнительные ИКР-вопросы (ТРИЗ-стиль)

Если фича прошла тест трёх аспектов, ещё две проверки:

- **(4) Можно ли решить ту же задачу существующим компонентом?** Перечислить — что уже есть в проекте, что **могло бы** выполнить эту функцию (возможно, с маленьким изменением)?
- **(5) Что бы сделал ИКР-вариант?** Описать гипотетический «идеальный» вариант — где функция выполнена, а нового кода/фичи нет (например: «использовать существующее поле X», «попросить пользователя дать данные сам», «отказаться от функции и предложить обходной путь»).

Если ответы на 4 и 5 показывают, что фича **лишняя** — отказываемся и фиксируем в Alternatives considered как «вариант: не делать».
