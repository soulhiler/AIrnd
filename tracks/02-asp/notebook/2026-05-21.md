## Узнал

- Структура программы — 6 фаз с явными gate-критериями. Закрытие трека — нормальный исход.
- Pre-registration через git-tag достаточно на начальном этапе, OSF можно отложить.
- В Треке 2 главная дизайн-развилка — расширение MCP или отдельный протокол — решается **после** литобзора, не до.
- **LSP vs MCP — разные парадигмы:** LSP — синхронизация состояния + точечные запросы (документ ↔ модель), MCP — context bus (resources, tools, sampling). ASP лежит между: code-specific семантика (как LSP) + LLM-агент-дружелюбная архитектура (как MCP).
- **Гипотеза для ADR 0001 (требует подтверждения):** ASP — это не отдельный протокол и не «толстый MCP server», а **typed code capability поверх MCP**. Сохраняет ecosystem MCP, добавляет типизацию и composability.
- **Tree-sitter сам по себе недостаточен** — даёт AST, но не name resolution и не cross-file. Нужен Stack Graphs или аналог сверху.
- **Темп выше планового:** AI-помощь сжимает «3 ключевые работы» с недели до нескольких часов. Это переопределяет реалистичные timeline — нужно пересмотреть оценки фаз.

## Update (тот же день, после смены приоритета)

По решению — приоритет на use cases вместо последовательного литобзора. Создан [`design/02-use-cases.md`](../design/02-use-cases.md):

- **20 use cases** в 5 категориях: Refactoring (5), Search & Navigation (5), Debugging (3), Understanding (3), Modification (4).
- **Источники:** GitHub issues (Aider #4113, #1540, Cline #4389), SWE-bench Lite, обзорная литература (Kiro, GitNexus, agentic-codebase), академические работы (SWE-Search ICLR 2025, SWE-Adept, Lita и др.).
- **Feasibility matrix** по каждому use case: MCP today / MCP + typed code capability / Отдельный протокол.
- **Подтверждение рабочей гипотезы:** ASP = typed code capability over MCP. Конкретные следствия: core primitives (findReferences, dependencies, impactAnalysis), composability через batched ops, cost-awareness через token budgets, sane defaults.

**Ключевые паттерны из анализа:**

1. Composability важна для 60% use cases (сейчас N+1 запросы).
2. Типизация важна для 70% use cases (агенты промахиваются на ad-hoc tool descriptions).
3. Semantic primitives нужны в ≥10 use cases — должны быть first-class.
4. AI-задачи (similarity, conventions, semantic merge) — 15%, требуют ML inside server.

**Прогресс Gate 0 → 1:** документально подтверждён gap; ADR 0001 может быть закрыт после ревью use cases человеком.
