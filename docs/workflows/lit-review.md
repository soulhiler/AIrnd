# Workflow: литературный обзор

Цель — превратить корпус релевантных работ в навигируемую базу, на которую можно ссылаться из дизайн-документов, ADR и препринта.

## Порядок шагов

**Шаг 0 (обязательно перед остальным): [Prior Art Search](prior-art-search.md).** Найти существующие решения в нашем проблемном пространстве и оценить % покрытия наших целей. Без этого глубокий литобзор foundational работ — преждевременен. Урок-источник: Трек 2 / GitNexus (см. файл prior-art-search.md).

После prior art survey:

- Если покрытие prior art **>80%** — пересмотреть scope трека до глубокого литобзора.
- Если покрытие **30–80%** — литобзор фокусируется на gap, не на полном пространстве.
- Если покрытие **<30%** — полный foundational литобзор как описано ниже.

## Правила записей

1. **Один файл = одна работа.** Никаких «папок с заметками по теме».
2. **Шаблон обязателен** — единый формат позволяет автоматизировать индекс.
3. **Relevance 1–5** — субъективная оценка для нашего трека. 5 = критично, 1 = по касательной.
4. **Цитаты с номерами страниц / параграфов** — чтобы потом восстановить контекст.

## Процесс на одну работу

```bash
make lit-add SLUG=author-year-keyword       # создаст файл из шаблона
# напр.: make lit-add SLUG=microsoft-2016-lsp
```

1. Заполни metadata-блок (title, authors, year, venue, link).
2. Прочитай работу. На полях отметь интересные места.
3. Запиши **TL;DR в 3 предложениях**: проблема, метод, результат.
4. Выпиши **ключевые claims** с короткими цитатами.
5. Опиши **методологию** в 1–2 абзацах.
6. Зафиксируй **gap** — что эта работа не покрывает и где наш потенциальный contribution.
7. Поставь relevance, теги.
8. Добавь строку в `INDEX.md` (или допиши руками — `lit-add.sh` делает это автоматически).

## Что НЕ делаем

- **Не пересказываем** работу целиком — это потеря времени.
- **Не суммируем abstract** — он и так доступен по ссылке.
- **Не пишем review больше 1 страницы** — длиннее = плохо отчуждённое знание.

## Когда работа неприменима

Не выкидывай — сделай короткую запись с relevance=1 и тегом `not-relevant`, чтобы потом не возвращаться.

## Связь с дизайн-документом

В конце Фазы 0 — сводный документ `tracks/<trk>/design/01-literature-review.md`:
- 5–10 страниц.
- Структура: проблема → существующие подходы → их ограничения → наш gap → план исследования.
- Ссылки на конкретные записи в `lit-review/`.
