# Workflow: pre-registration

Pre-registration — фиксация гипотез, метрик и методологии **до** сбора данных. Защищает от p-hacking, HARKing (Hypothesizing After Results are Known) и confirmation bias.

## Когда делать

Перед началом Фазы 3 (Измерение) каждого эксперимента. Обязательно — для любого результата, который пойдёт в препринт.

## Lean-подход через git

Не зависим от OSF. Достаточно git-коммита с timestamp:

```bash
# 1. Создай файл эксперимента
mkdir -p tracks/02-asp/experiments/exp-001-baseline
$EDITOR tracks/02-asp/experiments/exp-001-baseline/PREREG.md

# 2. Commit
git add tracks/02-asp/experiments/exp-001-baseline/PREREG.md
git commit -m "prereg(exp-001): baseline ASP vs ripgrep retrieval"

# 3. Тег
git tag prereg/exp-001/$(date +%Y-%m-%d)
git push origin --tags
```

Хеш коммита + signed tag = доказательство приоритета. Опционально дублируется в OSF.

## Структура PREREG.md

```markdown
# Pre-registration: exp-NNN

- **Эксперимент:** короткое название.
- **Дата pre-reg:** YYYY-MM-DD.
- **Связанная ADR:** NNNN (если есть).
- **Связанный дизайн-док:** path.

## Гипотезы

- **H1 (основная):** формальная формулировка с критериями принятия.
- **H2 (побочная):** ...
- **H0 (нулевая):** ...

## Метрики

- **Primary:** название, единица, как считается, ожидаемый диапазон.
- **Secondary:** ...

## Методология

1. Что измеряем.
2. На каких данных.
3. Сколько повторений.
4. Какие baseline.
5. Какие ablations.

## Stop conditions

- Когда останавливаем эксперимент (бюджет токенов, время, число запусков).
- При каких признаках — переоценка протокола.

## Анализ

- Какие тесты значимости.
- Какие доверительные интервалы.
- Что считаем «значимой разницей».

## Что НЕ будем делать

- Список соблазнов, от которых отказываемся: «не будем менять метрики post-hoc», «не будем добавлять модели после первого прогона», и т. п.
```

## После завершения эксперимента

В `tracks/<trk>/experiments/<exp-id>/`:
- `PREREG.md` — неизменён.
- `results/` — сырые данные.
- `analysis.md` — анализ строго по PREREG.
- `deviations.md` — если что-то пошло не по плану, **честно зафиксировать** что и почему.

Любое отклонение от PREREG — публикуется. Это не баг, это нормальная научная практика.

## Negative results

Если H1 не подтвердилась — пишем препринт «negative result», публикуем на arXiv. Это полноценный научный вклад.
