# Workflow: лабораторный журнал

Журнал — единственный артефакт, который связывает «что мы делали» с «что мы поняли». Без него retrospective и публикация превращаются в реконструкцию по памяти.

## Правила

1. **Ежедневно** в рабочий день. Пропустил — отметь пропуск с причиной.
2. **5–15 минут** на запись. Дольше — лишнее.
3. **Plain markdown**, файл = `tracks/<trk>/notebook/YYYY-MM-DD.md`.
4. **Под git** — не редактируй прошлые записи, добавляй новые. Опечатки можно править.

## Структура записи

```markdown
# YYYY-MM-DD

## Сделано
- ...

## Узнал
- ... (ссылки на `lit-review/`, ADR, эксперименты)

## Заблокировало
- ... (или: «ничего»)

## Next step
- одна конкретная вещь на завтра
```

## Команда

```bash
make notebook                    # создаст/откроет запись на сегодня
```

## Что НЕ записываем

- TODO-листы — для них есть Issues и `phase-status`.
- Reflections на полстраницы — для них есть weekly review (пятница).
- Личные заметки и черновики кода — для них есть `scratch/` (в .gitignore).

## Weekly review (по пятницам)

В записи добавляется секция:

```markdown
## Weekly review
- Прогресс vs gate-критерии:
- Что ускорило:
- Что замедлило:
- Корректировка плана на след. неделю:
```

## Связь с публикацией

В записи на Фазе 3–4 фиксируй конкретные числа экспериментов. На Фазе 5 это превратится в evaluation-секцию препринта.
